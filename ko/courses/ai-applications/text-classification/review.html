긴 글에서 학습 예제를 만드는 규칙

Window는 긴 글에서 잘라낸 짧은 입력 구간입니다. 다음 문자 예측의 Target은 그 입력보다 한 글자 뒤에서 시작합니다. Window 길이는 한 예제에서 읽는 문자 수이고, 이동 간격은 다음 예제를 어디서 시작할지 정합니다. 둘은 서로 다른 설정입니다.

원문의 구간이 겹치는 것과 모델의 State가 예제 사이에서 이어지는 것은 별개입니다. 13주차 실습은 각 예제를 별도로 처리합니다. 데이터 구간의 연결 관계와 실제 코드가 State를 전달하는 방식을 나누어 봅니다.

Sequence의 출력과 State 구분하기

RNN·LSTM·GRU는 현재 Input과 이전 State를 이용해 순서가 있는 데이터를 처리합니다. RNN과 GRU는 Hidden State를, LSTM은 Hidden State와 Cell State를 유지합니다. Gate는 어떤 정보를 얼마나 반영할지 조절하며 그 계산에 쓰는 Parameter도 학습됩니다.

모든 시점의 output과 마지막 State는 같은 배열이 아닙니다. batch_first=True일 때도 마지막 State의 축 배치까지 모두 같은 순서로 바뀌지는 않습니다. 반환값을 확인한 뒤, 문자별 Class 점수를 만드는 Linear가 어느 Tensor에 적용되는지 확인합니다.

단어 번호에서 문장 벡터까지

Token은 나눈 글의 단위, Index는 Vocabulary 안의 식별 번호, Embedding은 그 번호로 찾아오는 학습 가능한 벡터입니다. Index의 크기 자체가 단어의 의미나 감정의 정도를 나타내지는 않습니다. PAD는 길이를 맞춘 빈자리이고 UNK는 사전에 없는 Token을 나타냅니다.

14주차 모델은 PAD를 제외한 단어 벡터의 평균으로 문장을 표현합니다. Mean Pooling은 계산이 단순하지만 단어 순서를 보존하지 않습니다. 영상에서 배운 표현의 역할은 유지하면서, 실습에서는 현재 환경에서 실행되는 전처리와 모델로 중간 결과를 확인합니다.

학습 결과를 어디까지 해석할 수 있는가?

Loss는 선택한 학습 목적에 대한 값이고 Accuracy는 예측이 Label과 일치한 비율입니다. 두 값은 같은 지표가 아닙니다. 짧은 학습 데이터를 잘 맞혔다는 사실만으로 새로운 글에서도 잘 동작하거나 긴 문맥을 이해한다고 판단할 수 없습니다.

모델을 비교할 때는 데이터, 학습 조건과 평가 대상을 확인합니다. 데이터의 전처리나 Vocabulary를 바꾸면 모델 입력과 Embedding의 대응도 다시 확인해야 합니다. 도구 이름보다 입력·중간 표현·출력의 의미를 기준으로 결과를 설명해보세요.
