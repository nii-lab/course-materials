1. 입력·출력과 Feedback 경로

같은 시스템이라도 무엇을 입력으로 보고 무엇을 출력으로 보는지에 따라 Transfer Function이 달라집니다. 목표값을 따라가는 Reference Tracking과 외부 힘에 의한 변화를 줄이는 Disturbance Rejection을 구분하고, Sensor가 실제로 측정하는 신호를 확인합니다.

신호 관계를 식으로 정리한 뒤 MATLAB의 feedback 호출이 같은 블록 연결을 나타내는지 확인합니다. 실제 출력이 목표에 가까운지 보는 오차와, Controller에 들어가는 비교 신호는 Sensor 경로에 따라 다를 수 있습니다.

  • 모터의 전압을 바꾸는 경우와 부하가 바뀌는 경우를 떠올려보자. 두 상황에서 무엇을 입력과 출력으로 잡으면 모터의 변화를 설명하기 좋을까?

    10주차 · 기호와 운동 방향 정하기

  • 모터의 실제 속도와 Sensor가 보내는 전압을 블록선도에서 각각 찾아보자. Sensor Gain을 바꾸어 비교한다면 두 신호의 관계와 응답에서 무엇이 달라질지, 어떤 출력으로 확인해볼까?

2. Gain 변화와 Sensitivity

Gain의 크기와 Gain 변화에 대한 민감도는 서로 다른 질문입니다. Closed-loop Gain은 입력이 출력으로 얼마나 전달되는지를, Normalized Sensitivity는 Parameter의 작은 상대 변화가 결과의 상대 변화에 얼마나 전달되는지를 나타냅니다.

Sensitivity를 이용한 추정은 기준점 부근의 기울기를 사용합니다. 변경한 Parameter를 원래 식에 다시 넣어 구한 값과 비교하면 근사의 적용 범위를 확인할 수 있습니다. 정적인 증폭기 모델에서 얻은 결론을 동적인 시스템의 진동·안정성까지 그대로 확장하지 않습니다.

  • 9주차 증폭기에서 “더 크게 증폭하고 싶다”와 “부품의 값이 달라져도 출력이 덜 변했으면 좋겠다”는 요구를 비교해보자. 각각 어떤 값을 바꾸고 무엇을 비교하면 좋을까?

    9주차 · 결과를 문장으로 해석

  • Amplifier Gain을 바꾸는 실험을 생각해보자. 작은 변화에서 세운 예상이 큰 변화에서도 맞는지 알아보려면, 변화 폭과 비교할 결과를 어떻게 정해볼까?

    9주차 · 실제 변화와 근사 비교

3. 응답의 빠르기·진동·최종값

Rise Time, Settling Time, Overshoot는 응답의 서로 다른 특징을 나타냅니다. 빠르게 목표 근처에 도달하는 응답이 반드시 빨리 가라앉거나 최종 오차가 작은 것은 아닙니다. 그래프를 읽을 때는 입력 크기, 초기값과 최종값, 각 지표의 측정 기준을 함께 봅니다.

Second-Order 표준형의 Damping Ratio와 Natural Frequency는 Pole, 진동과 응답 속도를 연결해 줍니다. MATLAB의 step 그래프와 stepinfo 결과를 같은 응답에 대한 두 표현으로 읽습니다. 최종값을 dcgain으로 대조할 때는 안정한 모델의 Unit Step Response인지 확인합니다.

  • 응답 그래프에서 처음 올라가는 구간과 최종값 근처에 머무르는 구간을 나누어 보자. “더 빨라졌으면 좋겠다”는 요구가 어느 구간을 뜻하느냐에 따라 무엇을 비교해야 할까?

    11주차 · 응답 지표를 읽는 기준

  • 12주차 응답 곡선 하나를 골라, 진동이 줄어든 모습을 그려보자. 모델의 어떤 값을 바꾸어 그 모양에 가까워지는지 살펴볼까? 응답 속도도 함께 달라지는지는 무엇으로 확인할까?

    12주차 · 한 Parameter씩 비교

4. P·PI Control과 Steady-State Error

Steady-State Error는 충분히 시간이 지난 뒤에도 남는 목표와 출력의 차이입니다. 그 값을 논하려면 Closed-loop가 안정한지, 어떤 입력을 주었는지, 어떤 오차를 정의했는지 먼저 정해야 합니다. 유한 시간 그래프의 마지막 표본은 극한값과 같다고 단정할 수 없습니다.

P와 PI는 같은 Plant에서도 서로 다른 Pole과 오차 특성을 만들 수 있습니다. Integral Action의 효과를 해석할 때는 최종 오차뿐 아니라 Transient Response와 안정성도 함께 확인합니다. 이론적으로 예상한 오차와 시뮬레이션 결과를 비교할 때는 입력의 종류와 관측 시간을 함께 확인합니다.

  • 같은 Plant에 P 또는 PI를 연결한 실습에서 어느 쪽을 선택할지 고민해보자. 목표값에 가까워지는 정도 외에 어떤 응답 특징을 함께 보고, 비교할 Gain은 어떻게 골라볼까?

    13주차 · 같은 Plant에 P와 PI 연결

  • 시뮬레이션 끝에서 출력이 목표값과 아직 떨어져 있다. “아직 도달하지 않은 것”과 “계속 남는 차이”를 구분하려면 그래프의 어느 구간과 모델의 어떤 값을 더 살펴볼까?

5. Stability와 Performance Index

먼저 안정성을 확인한 뒤 성능을 비교합니다. 이번 실습에서 다루는 연속시간 Proper Transfer Function의 BIBO Stability는 상쇄 후 Pole의 위치로 확인합니다. Pole 계산과 Routh 판정은 같은 안정성 질문을 서로 다른 방법으로 다룹니다. 짧은 시간의 그럴듯한 그래프만으로 장기 동작을 판단하지 않습니다.

IAE는 오차의 크기를, ISE는 큰 오차를 더 강하게, ITAE는 늦게 남는 오차를 더 강하게 반영합니다. lsim으로 얻은 출력에서 오차를 만들고 trapz로 적분할 때, 입력·시간 구간·시간 간격을 맞추어야 합니다. 유한 구간에서 계산한 값은 그 구간에 대한 결과입니다.

  • 14주차의 Gain별 응답을 비교하려고 한다. 비교 대상에서 먼저 제외할 모델이 있을까? Pole 목록과 시간 응답을 함께 보며 선택 기준을 생각해보자.

    14주차 · 먼저 응답이 안정한지 확인

  • 한 번 크게 벗어났다가 빨리 돌아오는 응답과, 조금 벗어난 채 오래 남는 응답을 떠올려보자. 내가 사용할 장치에서 더 피하고 싶은 모습은 어느 쪽이며, 그 차이를 어떤 Performance Index로 비교해볼까?

    14주차 · 같은 시간 구간에서 Performance Index 비교

6. 모델·계산·그래프가 같은 조건을 나타내는가?

식과 수치 결과가 다르면 어느 한쪽을 곧바로 정답으로 삼기보다 입력의 크기와 부호, 계수 순서, 초기조건, 시간축을 확인합니다. 저차 근사 모델은 원 모델의 모든 동작을 보존하지 않으므로 어떤 입력·시간 구간에서 무엇을 비교했는지가 중요합니다.

  • 실습에서 만든 응답 그래프를 나중에 다시 그리려 한다. 모델·입력·시간축에 관해 어떤 정보를 함께 남겨두면 같은 결과를 재현할 수 있을까?
